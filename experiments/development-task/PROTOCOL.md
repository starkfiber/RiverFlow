# Complete-app SDK reuse comparison, frozen protocol

This is an experiment specification, not a result. It tests assembly of a bounded but complete Study Rooms app across CLI, browser GUI and read-only MCP. It does not compare building an entire language/runtime from scratch or establish universal superiority.

Freeze TASK.md, independent graders, SDKs and this protocol before model attempts. RF2 gets the source-pinned0.44 native compiler and reusable0.45 domain/storage, parser, I/O, HTTP/form and UI modules, without existing main/web/agent application entries. Python gets the conventional booking_sdk.py domain/store wrapper over standard-library SQLite and the standard library (datetime, json, http.server, html, secrets, sqlite3). Both start with equivalent room rules, durable revision-checked transactions and JSON-compatible state. SDK internals and storage formats differ and must be disclosed. Preparing these SDKs is pre-existing setup, outside the warm construction trial. Do not turn this into a cold development or language-only claim.

Use the same locally installed Codex CLI default model/configuration, explicitly disabling user-config plugins and persistent agent sessions. Record the actual resolved model when available, the exact CLI version/command, prompts, SDK manifests, source revision, per-attempt elapsed wall time, reported input/cached-input/output usage, tools, repairs, exit status and every failed/incomplete feature. No new API key or paid service signup. Do not alter user authentication/configuration. Only reviewed public code enters trial directories. No Kanika Memory/shared-compute routing.

Four fresh attempts, sequential counterbalanced order RF2/Python/Python/RF2, max900seconds each. Resource/time limits are identical. Stop a timed-out process and record incomplete/usage unavailable where the CLI did not emit a completed usage record. Do not estimate missing usage. Grade each unmodified final result from fresh processes. No human patching between attempt and grade. The benchmark may fail; keep all attempts in the denominator. Additional repairs are separately identified and cannot replace initial results.

Report individual results and pass fractions before any medians/usage ratios. A successful-attempt usage comparison requires all required features to pass; if the denominator lacks comparable successes, no savings percentage is established. Cached and uncached token counts are distinct; CLI usage is not a dollar-billing receipt. Compiler time, application runtime, package size, task elapsed and model usage are different measurements. Human learner/adoption observations are absent.

The independent grade covers real new/reopened files, validation, overlaps/adjacency, room/day independence, canonical IDs, large IDs, stale cancellation, simultaneous writers, GUI form protection/shared state, bounded read-only agent behavior and permission refusal. Browser visual judgement is kept distinct from semantic HTTP assertions. The native SDK has separate fault/recovery qualification; this construction experiment is not a new power-loss or hardware trial.
