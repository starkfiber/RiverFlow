# Matched C/D complete-utility trial — predeclared before provider calls

New useful tasks: C log severity summary and D duplicate inventory identifier
audit. Each task has a complete standalone json|html CLI, bounded selected-file
input, exact typed/escaped output, refusal cases and real output-failure checks.
They are new tasks, not another run of the earlier line/match trial. Prior studies,
repairs, transport failures, costs and evidence remain unchanged and separate.

Conditions:
- Manual imports only @rf2/v1/text.flow and its IO dependencies. It implements
  CLI validation, buffering, exact report shape and checked output itself. It may define its own report records/helpers under any names, counted as its
  returned source. It may not import SDK Report/text-report-cli modules, copy SDK
  sources, or use local files.
- CLI imports @rf2/v1/text-report-cli.flow, defines its synchronous callback and
  delegates the common plumbing to text_report_entry. It still implements the
  complete task-specific algorithm; the library supplies no severity/ID solution.

All conditions receive the exact same common language/API guide, style example,
task text and SDK bytes, compiler and independent grader. The condition instruction
is the only allowed-library difference. The common guide includes both allowed
Writer/text APIs and CLI/Report contracts; it contains no solution. Both tasks'
golden manual/CLI sources remain controller-only and never enter model prompts.

Balanced fixed order of initial attempts: C/manual, D/CLI, C/CLI, D/manual. Thus
manual precedes CLI for C and CLI precedes manual for D, with manual/CLI/CLI/manual
positions. This is a small ordered engineering trial, not a randomized population
study or a universal causal productivity result. Model deepseek-v4-pro, thinking
enabled, low effort; maximum10,000 completion tokens and180second HTTP/
195second controller observation for every call. Four initial calls; at most one
repair per attempt based only on actual independent compile/acceptance feedback.
Maximum8calls total. Complete an initial/optional repair before moving to the next
attempt. Do not repeat a transport, missing-output, length or policy failure;
those consume the initial attempt without automatic retry. A repair is permitted
only after returned source was reviewed and actually assessed as failing.

Before the first call freeze exact controller/transport/guide/style/task/oracle/
SDK/compiler identities and the successful golden validation receipt. Root reviews
and confirms the frozen hash. Each provider response is a source proposal only;
no commands or proposed binaries are executed. Separate reviewed source SHA256
is required before native assessment. No source may be changed in place; repair
is a new round with old source, feedback and all prior costs preserved. Provider
transport uses an explicit selected host/credential-file reference; no credentials
or company data enter these project files or prompts. No Memory/KHC/Chain use.

Native acceptance uses the unchanged independent oracle on synthetic files.
Golden controls must pass both plain and optimized modes first. Returned sources
are checked for the condition's API/import boundary, compiled and signed with the
same qualified compiler/SDK, then independently graded. Compile failure is not a
successful app. Partial output, unknown tool/API, wrong bytes, rejected valid input
or admitted invalid input is a failure, not a token saving.

Primary outcomes: complete tasks passing within the permitted initial+one repair,
with all input/output/reasoning/cache usage and request/build/test times retained
per round and combined per attempt and condition. Include all failed attempts in
condition spend. Unknown transport usage remains unknown, never zero. Reasoning
and cache counts are subsets, not extra tokens to add to provider totals. Report
provider usage as reported, not billing. Spend per passing task is undefined when
none pass or required usage is unknown. Do not use source size as a token proxy.
Do not combine earlier failed study costs with these matched conditions or erase
them; show historical studies separately when discussing the overall journey.
No native speed, universal model/hardware, field trial or stable-release claim.
