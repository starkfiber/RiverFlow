# Complete-utility C/D trial

The trial compares manual text/IO plumbing with the same SDK plus the reviewed
Report/CLI entry helper on two fresh synthetic tasks. Read PROTOCOL.md before
calling the provider; the complete tasks, usage including failures, and actual
acceptance outcomes are the unit of analysis. No source-length token proxy or
general causal productivity percentage is justified. Golden sources are controller
controls and are never shown to the model.

## Controller qualification

`artifacts/refinement-20261117/ai/golden-1/RESULTS.json` retains the first
qualification failure: D/CLI/plain timed out on its first two empty-file launches
under the fixed eight-second observation cap; its other 114 cases and all seven
other full suites passed. The cause is unresolved. Neither the timeout nor the
source/oracle expectations was relaxed.

`empty-replay-1/RESULTS.json` retains four diagnostic successful launches.
`empty-replay-2/RESULTS.json` records the bounded comparison using the original
CLI and manual binaries: ten JSON and ten HTML launches for each, 40/40 exact
outputs pass with the unchanged eight-second cap. This does not erase the initial
failure or prove its operating-system/background-load cause.

The single fresh full qualification `golden-2/RESULTS.json` passes all eight
builds: four C suites of 86 cases and four D suites of 116 cases, 808 checks in
total, plus explicit condition/compiler controls. Source, compiler and oracle
hashes match the first qualification. Default SDK remains unchanged; both
conditions receive exactly the same staged SDK bytes.

`study-1/FROZEN.json` binds those successful controls and exact protocol, guide,
controller, transport, source and SDK identities before provider calls. It is a
local reference; reproducible native binaries stay in the guarded disposable
cache. Separate root approval of its hash and returned source reviews remain
required by the controller. No stable release, Memory or KHC changes are made.

## Fresh provider outcomes

The frozen matched study is closed: **0/4 complete tasks** in six total requests
including permitted feedback repairs. Three responses returned the literal
placeholder rather than an implementation; two reached the completion cap;
one hit the transport observation deadline with usage unknown. Known provider
usage across the other five requests is 37,690 tokens. It is a lower bound, not
complete spend or billing. Request observation totals 564.001 seconds. Neither
manual nor CLI completed a task; no per-passing-task token cost or advantage can
be calculated. Invalid placeholder proposals failed the condition gate before
native execution. Native goldens passing is not provider task success.

A separately frozen one-initial/at-most-one-feedback-repair pilot changed only
the output contract. Its initial request failed in transport after 134.978 seconds;
no program or usage was recovered, and no retry was performed. That pilot is
closed; the proposed output-contract correction remains untested. It does not
replace any matched-study outcome or establish the placeholder failure's cause.

`EVIDENCE.json` contains public aggregate outcomes, exact receipts' hashes,
unknown-usage fields, the separate pilot and explicit scope. Full requests,
responses and preserved failures remain project-local under the artifact folders.
No claim that smaller/fewer tokens produce useful work follows from this sample.


## Transport improvement for future studies

A separate opt-in helper now preserves sanitized structured failure categories,
HTTP status, safe reason type, errno and elapsed time instead of a truncated
traceback prefix. It refuses redirects and credential reflection. Offline fake
HTTP/config/stream controls pass 63/63; see PROVIDER-TRANSPORT.md and its public
evidence. No live provider call or default transport replacement was performed.
The earlier unknown failure causes remain unknown. A pure payload builder also
recreates the exact reviewed corrected output-contract payload without a call.

The final transport correction classifies both write and explicit flush failures
as output errors and flushes within the guarded success path. Function-level
controls do not establish interpreter-shutdown pipe behavior. The earlier
61-control run and its source remain preserved.
