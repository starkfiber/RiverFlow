# Complete RF2 programs — bounded engineering completion campaign

Four sequential arms: C/manual, D/CLI, C/CLI, D/manual. An arm passes only if its
actual proposed source passes unchanged independent C86 or D116 cases in BOTH
plain and optimized compiler modes. Root inspects each returned source and passes
its exact hash before build/execution. No goldens, expected test inputs or task
solutions enter prompts. Native qualification remains Apple Silicon Mac only.

At most three source proposals per arm: initial, then at most two repairs based
only on that arm's actual compiler/grader feedback. Every prior request, response,
source, failure and usage is retained. A transport/missing-source/incomplete-output
failure closes that arm without blind request retries. Maximum12calls, sequential.
The reported-token threshold180000 is checked between calls, may be exceeded by
one response, and is not a hard dollar/token billing cap. Usage missing from a
transport result is unknown, never zero. No silent successor campaign.

Compared with the preserved prior 0/4 study, this explicitly changes the literal
placeholder output contract in BOTH tasks and system, clarifies exact HTML bytes
for BOTH conditions, selects disabled thinking/temperature0, raises completion
ceiling10000→16384, uses structured no-retry transport diagnostics, and allows
at most two reviewed feedback repairs. HTTP observation180s, outer process420s.
Consequently before/after totals describe these engineering runs, not a controlled
causal token-saving percentage, billing, or general model productivity claim.

The guide, tasks, controller, transport, unchanged oracle, qualified compiler,
shared source SDK and golden validation receipt are hash-frozen before inference.
Provider proposals are evidence/data, never commands. No live/stable compiler,
SDK, release, service, owner checkout, Memory, KHC or Chain mutation is authorized.
Unique evidence persists project-local; generated binaries use guarded cache.
