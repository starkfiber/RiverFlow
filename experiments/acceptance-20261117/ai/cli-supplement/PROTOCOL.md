# New CLI-library condition: predeclared supplemental engineering study

This is a new nonrandomized condition, not a causal token comparison. The earlier
Report condition encountered transport failure. Preserve that failure and every
initial/repair attempt; do not pool a new successful result into the old condition.
Do not use source size as a token, usefulness or billing proxy.

Two fresh calls only, fixed order task A then task B, once each. Model
`deepseek-v4-pro`, thinking enabled, low effort, maximum 10,000 completion tokens;
180-second HTTP and 195-second controller timeout. No automatic repairs/retries.
A transport failure, length completion, malformed proposal or failing program
consumes that task's one call. Continue to B without retrying A.

Use the existing amended Report guide and native-admitted common syntax unchanged,
then add the reviewed CLI API. Keep existing TASK-A/B, style, grader and SDK behavior
unchanged. Clarify that the imported CLI library performs the task's shared
argument/file validation and output plumbing; the callback must implement actual
line/search computation. No task-specific reference implementation enters prompts.

Before any provider call, freeze exact guide/task/style/CLI implementation, Report
API, controller, transport, acceptance oracle, SDK file identities and qualified
compiler hash. Supply a separately reviewed SDK root containing the new CLI module.
Inputs/receipts remain project-local. Existing transport uses an explicit authorized
host and credential-file reference through environment; never save credentials.
Only strict source proposals are admitted. Do not execute proposed commands.

Each returned source requires separate human/controller review and an exact SHA256
before compilation. Native assessment is a later guarded local action, never run
as part of call. Compile, sign and use the unchanged complete-task oracle. Report
all independent output/refusal/I/O results and actual generation/build/test times.
No live release or stable replacement is implied.

Report new A/B results separately from all supplied historical study records. For
historical records retain initial round and repair round usage/times distinctly;
include failed attempts and transport outcomes. Preserve raw provider usage,
served model, cached/reasoning fields and finish reason without double-counting
reasoning tokens if they are a subset of completion tokens. No inferred usage on
failed requests and no claim of billing savings. If no task passes, spend per
passing task is undefined. Original costs do not disappear when an app is repaired.
