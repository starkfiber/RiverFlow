# Preregistered Passage Desk construction comparison

This is a new bounded application composition task, distinct from the previous Study Rooms trials and the provided Document Audit application. It is not a randomized human trial or a from-zero SDK creation comparison.

Before any authoring call, freeze the task, black-box grader, Python text/MCP helpers, RF2 native compiler, SDK package manifest/module bytes and both SDK guides. Parent qualification and source review finish before timing. Retain a source-bound FROZEN.json and all actual results under a new ignored artifacts directory. No authoring calls if the frozen SDK/compiler fail qualification. No application entry or completed renderer is supplied in either arm.

Four fresh installed Codex CLI attempts run sequentially in fixed counterbalanced order Python, RF2, RF2, Python. Each has one 600-second budget, the same requested gpt-6.1-sol/low configuration and common task. Record the installed CLI version and actual emitted usage; do not infer served model identity if it is not emitted. No parent repair, follow-up prompt, trial substitution, optional rerun until success or altered grader after calls. Any later repair is a separate experiment with original failure intact. If authentication/provider or controller failure prevents measurement, retain it and state the gap; do not manufacture tokens or success.

The timer begins at the authoring process launch and ends when it exits or is terminated. It includes agent document reads, writing, own compilation/signing and self-tests. It excludes previously developed SDK/compiler, controller setup, independent grading and later replay. Native compile-only time is measured separately with exact final app source, not called full build time. Python has no ahead-of-time native compile requirement; record py_compile separately without pretending it is equivalent native compilation.

Every completed attempt is graded with the same immutable external assertions. Report grade, timeout, launch/author elapsed seconds, provider input/cached/output counts (cached input is a subset), command count, trace/source hashes and original delivery. Report all attempts, not successful means alone. Compare successful full deliveries only if both arms produce them and label the tiny sample exploratory. Token counts are provider usage, not an invoice or independent causal measure of language syntax. Warm helpers and their preparation/qualification costs are disclosed separately. No runtime, energy, universal productivity, learner or portability conclusion follows from this construction study.

The parent and reviewers share model/context lineage. The task's HTML is a static exported interface, not an interactive GUI. Existing nine Core MCP tools and permissions remain unchanged. No GitHub writes, remote workspaces, installation, Kanika Memory/shared compute or unrelated source disclosure occurs inside an attempt. Only reviewed public summaries/generated source may later be published by the parent through verified SFE.
