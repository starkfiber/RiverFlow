One 8×8 arrow becomes four different images. The transformations and these SVG images are produced by a native RF2 executable, using existing RF2 libraries for permissions, work limits, reference-versus-candidate checking and commit-after-success.

Recorded native results. This page displays captured executions. It is not an interactive browser compiler or a claim that these recipes require RF2.

What happens when the promise cannot be kept?

A recipe without permission, a work budget that is too small, or an overflowing brightness change is refused. A deliberately corrupted candidate also fails the independent reference comparison. No transformed state is committed in these cases. The qualification checks exercised these failures against actual native code.

What is different, and what remains unproven?

The demonstrated RF2 feature is composition: existing native contract and receipt libraries were reused in a visual application. Python, C++ and C# can implement these mechanisms too. This demonstration does not measure authoring time, actual AI tokens, speed superiority, hardware effects or exclusive capability. Content digests are unsigned records, not authentication or a security certification.

Mac ARM64 command-line app; no Python or Node user runtime. Python prepared test fixtures and this report. The source is a full native RF2 profile, separate from the playground's smaller Simple V3 learning subset.
