What improved, and what failed

  • All four languages received the same three algorithm choices: separate coordinates, a finite transition table, and packed state with exclusive branches.
  • The RF2 table candidate was slower: long-kernel median 20.890 → 27.712 ms in those studies. That loss is retained.
  • Packed state improved RF2's study median from 20.890 to 13.766 ms. The final selected-variant run above then measured 12.451 ms.
  • Each language's strongest observed long-batch variant was selected and rerun together. RF2 used packed state, C++ and Python used tables, and C# used the original branches.
Scope and remaining gaps
  • One shared Mac, no exclusive CPU isolation; timing ranges are retained in the downloadable summary. The repeated stream is not nonrepeating production traffic.
  • This compares pure CPython, one Clang configuration and managed .NET 8. It does not cover PyPy, Numba, NativeAOT, PGO or every compiler/runtime version.
  • No frame-rate, GUI authoring, energy, universal safety, hardware or broad AI-token advantage is demonstrated.
  • The app-level optimization is known state encoding and control flow, not new transistor physics or a general compiler pass.
  • The graphical rover uses the separate bounded Simple V3 reference worker. A native RF2 widget toolkit and complete GUI-development comparison remain unfinished.
