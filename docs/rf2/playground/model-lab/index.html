New to 3D? Start here.

You can view the pictures on this page immediately. To turn, inspect or edit the rover, use the editable scene below. Blender is a separate desktop application; this website does not install or launch it.

Download the ready-to-view Blender scene
  1. Save the file. Download rf2-rover.blend to your computer. The downloaded file is yours to keep.
  2. Open it in Blender. With Blender installed, choose File → Open and select the downloaded file. This recorded scene was checked with Blender 5.2.1 LTS; other versions are not qualified here. Keep automatic Python script execution disabled.
  3. Look around. Drag with the middle mouse button to orbit and use the wheel to zoom. On a trackpad, use Blender's viewport navigation gizmo at the upper right. The source model is already in the scene; you do not need to write code to inspect it.
  4. Try one reversible edit. Select a rover part in the Outliner, press G to move it, then Esc to cancel. Use File → Save As for your own copy, keeping the original intact.

Can I change the RF2 dimensions and build another rover?

Yes, through the existing local research pipeline. This page contains recorded outputs, not an in-browser 3D compiler. Download the source bundle and read its README before running anything. You need the qualified RiverFlow checkout/compiler and Blender; the bundle is not a standalone RF2 or Blender installer.

The native RF2 emitter accepts width 80–200 cm, length 100–300 cm and wheel radius 10–40 cm, with length at least four wheel radii. It computes the vertices and triangles. The reviewed Blender adapter turns that data into a mesh and supplies materials, lights, camera, renders and export. Use new output paths; keep the source scene and old results.

What RF2 does: validate dimensions and calculate geometry. What Blender does: build the scene from that data, display, shade, render and export it. This is not a native RF2 renderer or a claim that RF2 replaces Blender.

What was checked?

13 native parameter/refusal cases, 120 independent geometry assertions, 8 Blender input-refusal controls, and an actual clean GLB re-import. Mesh count, triangles, dimensions, materials, closed topology and missing dependencies were checked. Final skill audit passed with no warnings.

The original .blend keeps overlapping face UVs. The untextured GLB intentionally stores shared positions/indices/materials without UV or normal attributes; Blender derives flat normals on import. Earlier attribute-seam variants and a failed merge-only attempt remain in the evidence record.

What remains outside this demonstration?

No rig, collision, LOD, texture atlas, target-game-engine/frame-rate test, physical device, RF2 rendering engine, universal speed or actual AI-token benefit is established. Each part is a separate closed surface; physical interpenetration of the assembled parts is intentional.
