Evidence from actual programs

The local variables/input candidate passed 273 acceptance controls across quick execution and saved programs: 167 new cases, 102 legacy cases with one explicit grammar migration, and four IO/inspection controls. These are finite engineering checks for the captured V2 edition, not a classroom or human-learning trial. The new V3 candidate is tracked below.

Greeting, Rectangle and Workshop were built as real small CLI programs. Independent tests covered type errors, input limits, CRLF, EOF, pre-prompt source validation, build/inspect not consuming answers, and failed prompt writes preserving queued input.

Focus and Stretch share one countdown lifecycle library. Each app has six authored lines, while the library carries clock conversion, input readiness, progress, cancellation and EOF handling. 81 assertions passed. Shared code increases the first combined implementation; it does not make engineering work disappear.

Existing original lessons and the Core MCP boundary were replayed separately. New Simple input and Systems source still reject through bounded Core.

The costs stay visible

Saved constant Hello World stays 51,072 bytes and is byte-identical to the earlier image. The richer frontend and dynamic saved programs are 83,904 bytes. Interactive programs currently carry a native runtime engine.

Twenty-one rotated, launch-inclusive Hello trials per edition gave overlapping timing ranges. They do not establish a speed win. Source lines, actual AI token usage, developer effort, runtime latency and program size are separate measurements.

No universal speed, energy, security, hardware, human learning or AI-token saving claim is established by these results. Tests keep failed attempts and corrections, including actual carriage-return/input and source-location defects.

The Simple V3 candidate

The frozen local V3 candidate passed 622 independent controls through quick execution and saved programs. The native candidate implements if/else/end, repeat and while, all six numeric comparisons, and pure single-return numeric functions. Exact downloadable game/planner sources are included, with no claim that published stable Core 0.17 supports them.

The current design has up to eight functions with up to four numeric parameters, no global reads or IO in those functions, no recursive cycles, repeat count up to 1,000 and a shared runtime work budget of 4,096. Source types/names are checked even in skipped branches. Inspection lists potential inputs; it does not ask them. The numeric expression/function layer passed 2,104 assertions; an independent review passed 60 controls and promoted-root integration passed 75. These counts refer to their stated layers, not separate human users or a combined product-readiness score. Further work includes direct lowering, smaller images, signed/floating rules and supplied-answer agent execution.

The longer direction is one coherent system from human intent to applications, devices and operating systems. It does not follow that every target, hardware interface or app feature is implemented today.

Choosing a release

The local V3 learning kit is now included as a downloadable file with this site candidate. It is a Mac ARM64, ad-hoc-signed kit, not a notarized installer or universal release. Fresh extraction outside the checkout passed 58 controls, including native apps, saved-program parity, original lessons, a starter SDK subset and nine MCP tools.

The download is the exact locally qualified ZIP, with its checksum shown. Providing it here does not deploy this page, create a public release or update an installed plugin. Published releases elsewhere may still describe an older edition.
