# Audit of the 22-page RF2 review

The paper is a historical review of commit28b65ea, the installed0.36 plugin
snapshot. A fresh process rechecked its bound evidence hashes,22 readable pages
and all205 full commit hashes. These checks passed. They do not automatically
verify every sentence or proposal.

GitHub main at the start of this sprint was34c29bc, with**371** reachable commits
and the0.50 source candidate. The paper's205-commit list was complete for its
selected snapshot, **not current upstream**. The new import fix and regressions
were therefore reproduced against the actual0.50 compiler and exact composed
source rather than presented as a replay of the older code.

Corrections retained:

- Current SDK imports already check regular files; the observed remaining hang
  is in local imports. Do not sell existing SDK safeguards as a new feature.
- The old~25% cache loss was a different compiler/run. Current paired values are
  recorded in INTELLIGENCE-IMPORT-GUARD.json; no universal speed claim follows.
- WhatIF's scanner skipped RF2 source. The paper's lexical inventory and native
  controllers were explicit project tools, not built-in WhatIF native coverage.
- One complete DeepSeek critique is not evidence the model ran tests. Existing
  plan slot/stale-handle checks should not be advertised as new security fixes.
- The old local three-call guard was sequential and file-based, not a concurrency-
  safe hard billing cap. Timeout usage stayed unknown. This sprint makes no new
  model calls; its review gate grants no execution or publication authority.
- Admissible Mac/Core and embedded profiles are different. Cross-profile parity
  is a future experiment, not implemented hardware support.

The immutable historical paper and raw provider attempts stay project-local;
this reviewed correction and reproducible compiler/controller sources are the
publication artifacts. No private provider key, raw reasoning or Kanika Memory
record is published.
