# RF2Net local build and packaging qualification

24 November 2026. Development qualification only; not a production gateway or
public VPN release.

## Executed checks

| Area | Observed result |
| --- | --- |
| Mac app source build | Eight executables regenerated: six RF2 helpers and the C/Swift platform adapters |
| Same-host repeat build | All eleven bundle files were byte-identical |
| Native management source build | All six management executables regenerated byte-identically |
| Fixed x86 guest image | Regenerated byte-identically from its retained 18-file source snapshot |
| Isolated source-built app installation | Sixteen checks passed, including signatures, hashes, CLI/MCP, unenrolled status, tamper refusal and cleanup |
| Explicit source-input boundary | Eight refusal/validation checks passed |
| Guest quota write failure | Ten controls and 32 independently checked packet stages passed with synthetic clients and a controlled WAN peer |

The write-failure test injected EIO into the disposable guest’s quota journal.
Existing connections continued. New connections were refused while the quota
outcome was uncertain. The exact prior active record and unchanged journal were
checked, and reset restored the prior quota. This does not test torn writes,
post-write readback failure or physical power loss.

## What the build result means

The existing RF2 bootstrap compiler and installed Apple SDK/tools remain build
prerequisites. The fixed guest uses a checked assembly-reference path and RF2
boot-image emission. It is not a general RF2 x86 compiler or a new production
hypervisor. Same-host byte equality does not establish cross-host reproducibility.

QEMU is an external dependency. Its installed binary, formula, source-archive and
bottle identities were recorded. QEMU was not independently rebuilt in this
qualification. The project’s MIT licence does not replace QEMU, firmware or other
third-party licence obligations.

## Installation boundary

The tested package is deliberately unenrolled. It includes no private guest
configuration or remote peer script and correctly reports guest status unavailable
without enrollment. Native app process startup was checked; a complete first-time
interactive GUI journey was not.

Customer enrollment, complete firmware/dependency redistribution review,
public Internet VPN exit, physical NIC/ISP interoperability, broader protocol
coverage, long-run endurance and independent security qualification remain open.
These scoped passes do not establish OPNsense parity or production readiness.

No speed, energy, token-saving or universal security claim follows from these tests.
